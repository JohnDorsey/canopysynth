CANOPY step 13: timing measurements (build 18), taken on 2026-10-06.
Machine: AMD Ryzen 5 7600X (6 cores, 12 logical processors), Windows 10 (19045), Python 3.11.9, MSVC 2022, the optimised build (/O2 /fp:precise).
The programs: build\bench.exe (tests\bench\bench_main.c; powershell -File build.ps1 -Bench) and dev\measure.py. These are the raw outputs; the plan
(docs\canopy_plan.md, "Step 13: what was verified and measured") summarises them.

HOW TO READ THEM. The machine is not quiet in a way a program can control: the same row varies from run to run, by up to 2.7 times for the slowest of four runs of a
query row against the best. So section 1 gives the BEST of four runs of every row of bench queries (the run the machine disturbed least), section 2 gives three
complete runs of the scaling table, and sections 3 onwards are single runs. A first scaling table, taken before the per-thread counters of the benchmark were padded
to separate cache lines, showed a collapse at 6 threads that was false sharing in the benchmark itself; it is not kept.
